## Codebase Patterns
- Entity globals are in `ui/data.h` + `ui/data.c` (Badge, Machine, Tank, g_badges, g_machines, g_tanks, g_badge_count, etc.) — data_model.h/c are legacy files not in CMakeLists.txt
- Always use `g_tank_count` (runtime loaded count) not `TANK_COUNT` / `MAX_TANKS` for bounds checks in tank UI code; same pattern applies to machines (g_machine_count) and badges (g_badge_count)
- JSON config parsing lives entirely in `config_loader.c` which includes `ui/data.h`; no separate data_model.h needed
- `data_model.h` and `data_model.c` are NOT compiled (not listed in CMakeLists.txt); any changes to them are cosmetic/housekeeping
- The build environment requires proper IDF PATH setup to run `idf.py build`; individual object files can be compiled via `make -C firmware/build <target>.obj` after initial CMake configure
- ui_machines.c grid uses LV_FLEX_FLOW_ROW_WRAP with LV_SIZE_CONTENT height + scrollable screen — adding machines beyond 4 automatically adds rows; no structural changes needed for dynamic count
- Pre-existing CMake issue: `gdbinit.cmake:40` fails with "exactly three arguments" error in the ESP-IDF environment; this does not affect actual compilation, only CMake reconfigure step
- JSON config key for operators is `"people"` (not "operators"); config_loader looks for `cJSON_GetObjectItem(root, "people")`
- g_machines, g_tanks, g_badges are now heap pointers (not static arrays); `data_init_psram()` in data.c must be called in app_main() before config_load(); syntax for callers is unchanged (ptr[i] == arr[i] in C)
- cJSON hooks pattern: install `psram_malloc` hook before cJSON_Parse(), restore NULL hooks after — always restore before any early return to avoid leaking the hook state
- MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT is the correct cap combination for general-purpose SPIRAM allocations on ESP32-P4
- Operator login MQTT topic is `factory/operators/login` (not `nfc/badge`); payload includes uid, name, role, plant, ts (ms)
- Always use g_badge_count (runtime loaded count) not BADGE_COUNT (static max) when iterating g_badges
- LVGL symbol set: LV_SYMBOL_USER does not exist in this version; use LV_SYMBOL_CALL for person/badge tab icon
- LVGL flex API: lv_obj_set_flex_shrink() does not exist; use lv_obj_set_flex_grow() on the expanding sibling only
- LVGL flex sizing: lv_obj_set_size(obj, LV_FLEX_GROW(1), h) is invalid; use lv_obj_set_size(obj, 0, h) + lv_obj_set_flex_grow(obj, 1)
- format-truncation is -Werror in this build; snprintf buffers must cover worst-case field sizes (dept 32 + plant 32 + decoration = 80+ bytes)
