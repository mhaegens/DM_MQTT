## Codebase Patterns
- Entity globals are in `ui/data.h` + `ui/data.c` (Badge, Machine, Tank, g_badges, g_machines, g_tanks, g_badge_count, etc.) — data_model.h/c are legacy files not in CMakeLists.txt
- JSON config parsing lives entirely in `config_loader.c` which includes `ui/data.h`; no separate data_model.h needed
- `data_model.h` and `data_model.c` are NOT compiled (not listed in CMakeLists.txt); any changes to them are cosmetic/housekeeping
- The build environment requires IDF_PATH setup; source /Users/I584748/esp/esp-idf/export.sh before idf.py
- Pre-existing CMake issue: `gdbinit.cmake:40` fails with "exactly three arguments" error; does not affect compilation
- JSON config key for operators is `"people"` (not "operators")
- SPIFFS: use `spiffs_create_partition_image(spiffs spiffs_image FLASH_IN_PROJECT)` in main/CMakeLists.txt; partition label must match partitions.csv 'Name' column; source files go in main/spiffs_image/
- Config load order: SPIFFS (/spiffs/sapdm_config.json) -> SD card (/sdcard/sapdm_config.json) -> embedded DEFAULT_CONFIG_JSON
- `esp_vfs_spiffs_register` returns `ESP_ERR_INVALID_STATE` if already mounted -- treat same as `ESP_OK`
- Build: `idf.py build` fails with cmake 4.3.2 due to `remove_duplicated_flags` breaking in toolchain cmake; use compile_commands.json + direct riscv gcc to check individual files
- LVGL is pinned to CPU1 (task_affinity=1 in bsp_display_cfg_t); all other tasks (sim, mqtt, btn, console) should use CPU0 or auto to avoid contention
